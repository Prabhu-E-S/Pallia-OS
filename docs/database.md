# Database

PostgreSQL 16, accessed through SQLAlchemy 2.0 (ORM) with Alembic migrations.

## Connection

| Variable      | Value                                              |
| ------------- | -------------------------------------------------- |
| `DATABASE_URL` | `postgresql+psycopg://pallia:pallia@localhost:55432/pallia` (published port) |
| Driver        | `psycopg` (v3)                                     |

The root `.env` also sets `POSTGRES_PORT=55432` because a Windows-native
PostgreSQL already occupies the default `5432`.

## Conventions

- **UTC everywhere.** `DateTime(timezone=True)` columns; the API stores aware
  datetimes and the frontend renders in the browser's local timezone.
- **Surrogate keys.** Every table uses `id` = `uuid` (Python-side `default=uuid4`).
- **Audit timestamps.** `created_at` / `updated_at` are columns on every
  aggregate; rows are *not* soft-deleted in Phase 1.
- **Enums as strings.** Domain enums live in `app/models/enums.py` and are
  stored as `String` columns with column-level `CheckConstraint`s. TEXT storage
  keeps migrations simple and reads fast; a native `ENUM` type can replace it
  later if we need the database to reject invalid values on its own.
- **Booleans / numerics.** Plain `Boolean`; `Numeric(12,2)` for clinical
  scores.

## Multitenancy

Single database, tenant-safed by `organization_id` on every tenant-owned
table. All queries go through org-scoped services
(`app/services/*.py`) that always filter by the actor's `organization_id`.
No `Row Level Security` is configured in Phase 1 — enforcement happens in the
service layer, which is the single write path.

## Schema overview

```
organizations (id, name, subdomain, is_active, trial_end, created/updated)
├─ users (org FK, email, display_name, role, is_active, times…)
├─ patients (org FK, mrn, name, dob, gender, status, address, contacts, record…)
│   ├─ care_teams (org FK, patient, member user, role_in_care, primary…)
│   ├─ caregivers (org FK, patient, name, relationship, best_time, contact…)
│   ├─ care_plans (org FK, patient, status, goal_note, signed/valid…)
│   │   └─ care_goals (plan FK, title, priority, status, target/achieved…)
│   ├─ observations (org FK, patient, author user, type, value, unit,
│   │                 severity, timestamps, note, source)
│   ├─ visits (org FK, patient, scheduled_at, duration_minutes, status,
│   │           location, ended_at, summary)
│   ├─ tasks (org FK, patient, assignee, source_visit, type, priority,
│   │          status, due_at, completed_at, title, description, outcome)
│   ├─ timeline_events (org FK, patient, event_at, type, payload_json)
│   └─ alerts (org FK, patient, severity, kind, message, status,
│              acknowledged_by/at)
└─ audit_logs (org FK, actor, action, entity_kind/entity_id, patient FK, details_json)
```

## Migrations

```bash
make migrate           # alembic upgrade head
make new-migration MESSAGE="add_something"   # autogenerate
```

Initial schema was generated from the models (`0001_initial_schema`). Always
review autogenerated migrations before committing.
